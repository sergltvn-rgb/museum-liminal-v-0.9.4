# МНЕМОС — UI-референсы

Референсы для блока 10 интерфейса Museum Liminal. Изображения предназначены для оценки **композиции, плотности, ритма панелей и распределения цвета**, а не как финальные макеты с готовым текстом.

## Общие правила

- Основа: советский научный музей будущего, система конца 1990-х с модернизацией 2003 года.
- Прямоугольные панели, нулевые скругления, жёсткие рамки 2–3 px, непрозрачные фоны, пиксельный шрифт.
- Палитра: `#111518`, `#435865`, `#C6B994`, `#81A88A` и максимум один редкий акцент на экран.
- Зелёный означает только штатную работу.
- Без неона, glow, glassmorphism и современного «мобильного» UI.
- Сгенерированный текст считать рыбой: при реализации использовать локализацию проекта.

## Каталог

### 01 — Терминал диагностики МНЕМОС
**Файл:** `01_terminal.jpeg`

Полноэкранный пост наблюдателя: сводка события, стабильность 61%, диагностические признаки, рекомендуемый протокол, план музея и журнал событий. Использовать как основной референс структуры терминала. Янтарный — только для состояния стабильности.

### 02 — Терминал, третья ночь
**Файл:** `02_terminal_corrupted.jpeg`

Повреждённая версия терминала. Важны наложение окон, битые сегменты, неизвестные глифы и сохранение читаемости критических строк. Искажение должно лежать поверх базовой разметки.

### 03 — Минимальный HUD наблюдателя
**Файл:** `03_hud.jpeg`

Референс расположения таймера, задачи, прибора, контекстного действия и индикатора воздействия. При реализации убрать лишние диагностические окна из центра: не менее 90% кадра должно оставаться свободным.

### 04 — Планшет CCTV
**Файл:** `04_cctv_tablet.jpeg`

Физический инвентаризационный планшет 4:3. Слева схема камер, справа текущий кадр и архивное фото. Аналоговый шум применять только к видеопотоку; UI должен оставаться резким.

### 05 — Удерживаемое сканирование
**Файл:** `05_scanning.jpeg`

Четыре стадии процедуры, текущий и архивный кадры, регистрационные перекрестия. Использовать сегментированную прямоугольную шкалу, не круговой progress ring.

### 06 — Инвентарь приборов
**Файл:** `06_inventory.jpeg`

Двенадцать приборов в плотной двухколоночной сетке и единая панель выбранного прибора. Общая рамка одинакова для всех приборов; меняется только датчик.

### 07 — Шесть датчиков
**Файл:** `07_sensors.jpeg`

Сравнительный лист: уровень наклона, временные треки, дистанция до разрыва, температура и след, подавление объекта, механический счётчик заряда. При реализации унифицировать размеры и крепления рамки.

### 08 — Главное меню
**Файл:** `08_main_menu.jpeg`

Экран входа в музейную систему вместо обычного игрового меню. Слева команды, справа фасад музея и служебная информация, снизу загрузочный лог. Настроение — холодное, бюрократическое, негостеприимное.

### 09 — Предупреждение об аномалии
**Файл:** `09_anomaly_warning.jpeg`

Красная жёсткая рамка и диагональная штриховка. Тревога должна читаться по форме даже в градациях серого. Фон не размывать, glow не использовать.

### 10 — Отчёт о завершении смены
**Файл:** `10_end_shift_report.jpeg`

Табличный музейный отчёт: смена, длительность, устранённые события и итог. Единственное фиолетово-белое выделение — расхождение между числом зарегистрированных закрытий и устранённых событий.

**Статус:** ожидает генерации — лимит генератора исчерпан.

### 11 — Настройки
**Файл:** `11_settings.jpeg`

Вертикальные вкладки и плотный список параметров: масштаб UI, высокий контраст, уменьшение вспышек, RU/EN. Длинные русские строки должны переноситься без обрезки.

### 12 — Искажение HUD аномалией
**Файл:** `12_anomaly_distortion.jpeg`

Базовая компоновка не двигается. Поверх неё: следы предыдущего таймера, горизонтальное смещение одного слоя, зеркальная служебная подпись и строка `НАБЛЮДАТЕЛИ: 2`. Критические значения остаются читаемыми.

**Статус:** ожидает генерации — лимит генератора исчерпан.

## Замечания по реализации

1. Не копировать случайные надписи с генераций.
2. Все экраны проверить в RU/EN, `large_text`, high contrast и reduced flashes.
3. Аномальные эффекты не должны менять размеры `Control`/`Container`.
4. Сначала добавить пиксельный шрифт с полной кириллицей, затем переносить композицию.
5. Перед импортом в игру оставить исходники здесь, а оптимизированные игровые текстуры хранить отдельно.
